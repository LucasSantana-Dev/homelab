## Tier 1 — Strong fit, ship after k3s drain (the "core seven")

### 1. Immich — Google Photos replacement
- **Gap**: Nextcloud Photos has a clunky mobile experience; you have NC Mobile but no real photo backup story (memory notes NC mobile sync but Photos is barely used). Immich has best-in-class iOS/Android auto-upload + ML face/object recognition.
- **Why this stack**: NC running already so you'd keep Files there; Immich becomes the photo library. CF Tunnel hostname `photos.luk-homeserver.com.br` slots in cleanly. Tailscale for fast LAN browsing.
- **Footprint**: ~600 MiB idle, ~3 GiB during ML reindexes. CPU spikes at upload. Postgres + Redis included (can share NC's Redis).
- **Risk**: ML model needs ~1 GB extra RAM during initial index of large libraries. Throttle by disabling face/CLIP if RAM-tight.
- **Next PR**: `feat: add Immich photo service` — new `compose/photos.yml`, Caddy + CF tunnel route, homepage card under new Photos group.

### 2. Forgejo (or Gitea) — private git mirror + private repos
- **Gap**: All your code lives on `github.com/LucasSantana-Dev`. No offline mirror. Token leaks → no fallback. Forgejo gives you (a) GitHub mirror for resilience, (b) private repos that never touch GH for scratch work, (c) Actions runner if you want CI parity offline.
- **Why this stack**: You ship code daily (Lucky, vsantana-org, Craftvaria, homelab itself). Cloudflared + Caddy already set up to expose `git.luk-homeserver.com.br`. Existing `local-registry:2` container shows you've already invested in a private supply chain.
- **Footprint**: ~250 MiB idle. Postgres optional (sqlite default fine for personal use).
- **Skip if**: you don't care about offline access. GitHub free private repos cover the "private code" case.
- **Next PR**: `feat: add Forgejo for private code mirror` — `compose/git.yml`, mirror task that pulls your top 10 GH repos nightly.

### 3. Linkding — bookmark archive with full-text search
- **Gap**: You have browser bookmarks in Brave. No central archive, no search across them, no archived snapshots when sites die. The screenshot at session start showed your sidebar with "Pessoal/Trabalho/Estudos/Música" folders — that's the seed dataset.
- **Why this stack**: Tiny footprint, supports tags + bulk import from Brave's bookmarks export. Offline snapshot via singlefile.
- **Footprint**: ~50 MiB idle. SQLite, no DB to manage.
- **Next PR**: `feat: add Linkding bookmark service` — same shape as Gatus.

### 4. Miniflux — RSS / news reader
- **Gap**: No personal feed reader in inventory. You consume tech blogs and music reviews (browser bookmark "Music Reviews" hint). Miniflux dedups + syncs read state across devices.
- **Why this stack**: Pairs with Linkding — RSS in, save-for-later out. Tiny.
- **Footprint**: ~30 MiB idle, Postgres-backed. Use shared `nextcloud-db` MariaDB? No — Miniflux wants Postgres. Add a small `pg17` instance, ~80 MiB.
- **Skip if**: you read everything via Brave's built-in feed reader.

### 5. n8n — automation (re-deploy in docker)
- **Gap**: `compose/apps.yml` already defines n8n. K3s `n8n-n8n` is scaled to 0. No active workflow automation today, but Lucky-related glue (Discord notifications), Pi-hole alerting on outage, and CF cache purges all want this.
- **Why this stack**: You already wrote the compose entry. Memory notes "automation glue" pattern. Forge MCP gateway is gone, so n8n becomes the cross-tool orchestrator.
- **Footprint**: ~250 MiB idle, ~500 MiB under load.
- **Next PR**: `feat(n8n): bring up docker-side n8n with retained k3s data volume` — only the cutover work, the service block already exists.

### 6. Home Assistant (migrate from k3s to docker)
- **Gap**: HA runs in k3s `apps` namespace today. K3s drain (B1) breaks it. `compose/automation.yml` already has the docker definition; just needs cutover.

### 7. LiteLLM proxy — single OpenAI-compatible endpoint

- **Footprint**: ~150 MiB idle. SQLite by default.
- **Next PR**: `feat: add LiteLLM proxy in front of providers` — `compose/ai.yml`, retro-fit Open WebUI to point at LiteLLM.
